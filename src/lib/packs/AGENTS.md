# Cards, packs and combining

- Card combining: CE tables live in src/game/combining.ts (SQL copy: card_level_requirement_table(), see the SQL-constants rule); combines run only through service-role combine_player_cards (one transaction, audit row in card_combinations, absorbed copies get is_combined + combined_to + status 'combined'); ranked reads the best usable level per card from the security-invoker view player_card_stacks (owned available + rented-in copies); lockedTeam clamps troop levels by the summoner (playedLevels) (why: no client-side levelling, ranked uses server-owned levels).
- player_cards holds one row per unique card copy (never stacked; combined copies keep their row) and cards carries the supply counters (total_printed bumped by pack reveal/chest open, total_combined by combine_player_cards, circulating_supply generated, optional max_supply hard cap); only those SQL procedures write them and the catalog loader never touches them (why: supply is auditable and can't drift or be reset by a catalog reload).
