# Economy
- Balances (Credits whole-number, Coins 8-decimal) live in player_items (item_type 'currency') and change only through the server-only record_ledger_entry SQL function, called via recordLedgerEntry in ledger.server.ts with a deterministic idempotency key (ledgerKey); players only read their own balances/ledger and amounts travel as exact decimal strings (why: no double payouts, no client-side minting, no float rounding of Coins).
- Pack purchases debit Credits inside purchase_packs via record_ledger_entry with key pack_purchase:{player}:{requestId}; a replayed key returns the original purchase and never adds packs twice (why: double-click/retry safety).
- Ranked rewards are accrued in SQL inside finalize_match (accrue_match_rewards writes matches.p1_reward/p2_reward; reward_day_players derives each player's daily wins, shares and missions from them) and paid by settle_reward_day via record_ledger_entry with keys reward:match:{day}:{player} / reward:daily:{day}:{player}; a daily pg_cron job runs settle_due_reward_days, and each settled day is a treasury_ledger reward_day row, and days whose month has no published budget (treasury_ledger budget row) stay open (why: atomic with the rating change, idempotent payouts, no Coins promised before treasury funding).
- src/game/rewards.ts mirrors the SQL reward formula and missions for display and tests; change both together (why: the database is authoritative, the UI must show the same numbers).
- Market and rentals run only through service-role SQL functions (market_list_card/market_buy/rental_rent/... called from src/lib/market/market.functions.ts); a listed or rented-out card is locked (player_cards.status) and the player_card_stacks view counts owned-available + rented-in copies; ended rentals are handed back lazily by expire_rentals before ranked and market reads (why: one card can never be sold, listed or played twice, and no polling job is needed).
- The 5% trading fee is split by split_trading_fee and recorded as treasury_ledger flow rows (reward_vault/burn/operations), as are reward payouts out of the vault; src/game/market.ts mirrors the split for display (why: the public treasury report is built only from recorded flows).
- Treasury wallets, balance snapshots and Coin acquisitions (snapshots/acquisitions = treasury_ledger rows; flows, snapshots and acquisitions share that one table, told apart by entry_type) are written only by admins (user_roles + has_role, checked in src/lib/treasury/treasury.functions.ts); the monthly budget is computed by calculate_reward_budget from the latest reward-vault snapshot plus last month's vault acquisitions and fee returns, and published via publish_calculated_reward_budget (why: budgets come from Coins the project verifiably holds).
- Division chest Credits are paid inside open_division_chest (entry type chest_credits, key chest:credits:{chest}:{roll}); chest Coin shares are paid only at season close by close_ranked_season from CHEST_COIN_POOL_SHARE of that season's League pool slice (entry type chest_reward, key reward:chest:{season}:{player}, plus a reward_payout treasury_ledger flow) and pay nothing when the month has no published budget (why: no Coins promised before treasury funding).
- Deposits and withdrawals go through the transactions-pending queue: deposits are credited only after the Solana payment is verified (treasury, mint, memo tag) with key deposit:{signature}; withdrawals debit and queue in one step via request_withdrawal (key withdrawal:{txid}) and are refunded via refund_withdrawal (key withdrawal_refund:{txid}) only when the payout certainly never left; preview-only test deposits/withdrawals use the same path and are refused in production builds (why: no double credit, no double payout, no test balance on the live game).
