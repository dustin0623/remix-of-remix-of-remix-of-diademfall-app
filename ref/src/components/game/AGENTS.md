# Hero presentation
- HouseContent is a read-only house board with occupancy and energy display, without a Rest trigger or roster drawer. Hero assignment and removal belong to the Heroes collection's shared actions; the House route and Test UI house view do not accept mutation adapters. Empty-house guidance points to Heroes. Why: players manage house assignments in one place.
- FusionContent uses the unframed hud-fusion shell and swaps forge → eligible collection → review → request/result in place. Only review confirmation calls the route/mock adapter; FusionOutcome carries structured success/hero data, and quotes come from FUSION_RECIPES/fusedLevel. Collection picks are revalidated against current availability, capped at three, and retained when editing review. The sticky collection header reuses HeroCollectionFilters; Review fusion includes the selection count and floats at the bottom center above the scrolling gallery padding, with no full-width selection bar. Test UI uses its own fee balance and shared fusion rolls without wallet operations. Why: the scene matches Shop while selection/reveal interactions cannot consume heroes or charge fees.
- SummoningDialog owns only the quantity confirmation; SummoningReveal replaces the Shop content in-page for waiting and the face-down card reveal (three cards per row, leftovers centred, Flip all / Skip bar). MintHeroesContent calls the wallet-validated mint once before showing awarded heroes; flipping, revealing all and closing are presentation only. Card backs use the 300 × 420 summoning-card-back.png, with hover/focus glows from HERO_RARITY_DEFS tint and reduced-motion support. Why: reveal interactions cannot charge again or alter the awarded heroes.
- HeroArtwork resolves character identity and rarity through local PNG paths in public/assets/heroes/<rarity>; these folders contain the framed portraits, without JSON asset pointers. Shared cards, details, house roster, fusion selection and mint reveals use it, while Phaser/HeroSprite keep animated sheets. Why: one portrait mapping avoids duplicate framing and leaves gameplay unchanged.
- MarketplaceContent shares Heroes' unframed gallery, grid and sticky controls; price plaques show only Yours for owned listings. BuyPanel uses explicit live/mock purchase adapters and review showing price, burn, seller proceeds and balance; no timed holds or transaction entry. Test UI shares wallet balance, inventory and purchase history across views. Why: the same confirmed purchase presentation runs without private operations in previews.

- Heroes and Test UI wrap collection cards in nonmodal HeroActionsPopover, aligned right/end to grow upward from the card bottom with viewport collision handling. HeroActions popover layout exposes energy-related deployment rules, Upgrade, Sell/Cancel sale and house actions directly; level/sale/house confirmations keep their existing dialogs and authenticated route adapters. Marketplace uses the same popover with a price heading, seller row and BuyPanel (disabled for own or unaffordable listings). Test UI sale confirmation uses an explicit preview adapter without wallet reads. Why: cards stay visible while common actions are accessible beside the selected card.

- HeroesDrawer fills the viewport with a transparent gallery above a single 65% black SheetOverlay. It uses a brief opacity fade instead of sliding the entire gallery, with reduced-motion support and no background image or blur. The shared seven-column grid and HeroCollectionFilters in selectorsOnly mode keep stationary selectors/Close above one gallery scroller, with no selected-team tray or batch deployment. Cards open HeroActionsPopover; Deploy/Recall sends one scene command immediately. Upgrade and Sell remain disabled inside the live scene where their authenticated collection adapters are unavailable.

- Deploy and Heroes group their filtered collections through sortCollectionHeroes: Deploy uses working/idle/house/resting; Heroes (including Test UI) uses working/house/resting/idle. Each group retains the strongest-first rarity/stat ranking by default; explicit sort selectors apply within groups. Status matches card badges: housed first, then onMap working, full energy idle, otherwise resting. The drawer memoizes the sorted list so popover state changes do not repeat filtering/sorting. Marketplace and Fusion retain their existing sorting.
